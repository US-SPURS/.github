## Mission

The **United States Department of Special Projects and Unified Response Services (US-SPURS)** coordinates specialized projects, unified response capabilities, and interoperable technology across organizational and operational boundaries.

Our public engineering work focuses on systems that are **secure, observable, interoperable, accessible, reusable, and designed for long-term resilience**.

> **Operating principle:** Complexity should be absorbed by the system—not transferred to the people using it.

### ATLANTIS AI Multi-AI System

**ATLANTIS AI** is the unified AI and autonomous-execution architecture within the US-SPURS technology ecosystem. Publicly developed components are designed around capability discovery, request normalization, multi-AI arbitration, task-graph execution, verification, policy enforcement, and auditable human-governed automation.

**SWARM**, **HITMAN**, and related agent/automation capabilities are treated as integrated modules within the broader ATLANTIS architecture rather than disconnected products.

### OmniCode

**OmniCode** is the semantic-interoperability initiative for expressing intent, capabilities, data relationships, operations, and system meaning across heterogeneous environments.

> Different systems should not need to think alike in order to understand one another.

## Engineering Baseline

| Area | Direction |
|---|---|
| **Security** | Least privilege, protected change paths, dependency review, secret protection, auditable controls |
| **Software supply chain** | Reproducible builds, dependency visibility, SBOM/provenance and signed-artifact capabilities where implemented |
| **Accessibility** | Semantic interfaces, keyboard access, automated accessibility testing, Section 508/WCAG-oriented engineering |
| **Interoperability** | Open APIs, documented schemas, machine-readable metadata, reusable integration patterns |
| **Operations** | Observable systems, explicit failure modes, rollback paths, recovery planning |
| **Governance** | Pull-request review, documented decisions, repository ownership, lifecycle visibility |
| **Automation** | Human-governed automation with authorization boundaries and verifiable execution |

> [!NOTE]
> Repository-specific controls and compliance status are defined by the applicable repository and system documentation. Organization-level descriptions are not certification claims.

## Build With US-SPURS

Public repositories are intended to be understandable and reviewable by developers, researchers, designers, security professionals, technical writers, public-interest technologists, government partners, and community contributors.

**Start here:**

1. Read the target repository's `README.md`.
2. Review the organization [Contributing Guidelines](https://github.com/US-SPURS/.github/blob/main/CONTRIBUTING.md).
3. Review the [Code of Conduct](https://github.com/US-SPURS/.github/blob/main/CODE_OF_CONDUCT.md).
4. Check existing issues and discussions before opening duplicate work.
5. Use a focused branch and pull request.
6. Include tests and documentation with implementation changes.
7. Resolve automated and human review findings before merge.

## Security

Security vulnerabilities **must not be reported in public issues, discussions, pull requests, commits, or repository comments**.

Use the reporting instructions in the organization [**Security Policy →**](https://github.com/US-SPURS/.github/blob/main/SECURITY.md).

Public engineering is designed around continuous verification rather than implicit trust based solely on network location or repository membership.

---

## Open Development

US-SPURS uses a **default-open direction** for work that can be made public without creating security, privacy, legal, contractual, or operational risk.

Open development means publishing enough context for another person to understand:

**what was built · why it exists · how it works · how it is governed · how it is secured · how to contribute · how to verify it**

Public-domain treatment and repository-specific licensing are defined in each repository's `LICENSE` file. Organization community resources currently use the **CC0 1.0 Universal** public-domain dedication where stated.
